# Review Pull Requests

## Checklist

- [ ] Does the code follow existing patterns and conventions?
- [ ] Are there any security issues (hardcoded secrets, injection risks)?
- [ ] Are there appropriate tests? Do they cover edge cases?
- [ ] Is the code well-structured with clear naming?
- [ ] Are there any performance concerns?
- [ ] Are error cases handled gracefully?
- [ ] Is documentation updated (README, API docs, inline)?
- [ ] Does the PR description explain the what and why?
- [ ] Does `git diff` look clean (no formatting noise, no unrelated changes)?
- [ ] Run lint and tests
